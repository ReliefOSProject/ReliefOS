# ReliefMath

ReliefMath 是原生 C++/FLTK 数学公式编辑器。一个 `.rmath` 文档可保存多条公式；中间编辑 LaTeX 源码，右侧离线渲染。程序使用系统现有的 FLTK `gtk+` 控件和中文字体，按 ReliefWord、ReliefExcel 的分组功能区排版。

## 使用

从办公应用菜单启动，或运行 `reliefmath [document.rmath]`。左侧用于筛选、选择和管理公式；中间提供行号、命令高亮、括号匹配和源码编辑；右侧显示透明背景预览。分栏可拖动，列表与预览可在“视图”页显示或隐藏。窗口随桌面工作区调整，最小尺寸为 960×600。

| 功能区 | 工具 |
| --- | --- |
| 开始 | 剪贴板、公式增删改名和副本、排序、查找替换、模板、收藏、导出 |
| 符号 | 希腊字母、运算与关系、箭头、集合、逻辑及完整符号目录 |
| 结构 | 分数、根式、上下标、积分、求和、矩阵、分段、对齐和文字向导 |
| 排版 | 字号、行内/显示模式、颜色、边距、字体与重音 |
| 视图 | 缩放、适合预览、分栏显示、示例文档与帮助 |

内置目录含 131 个插入项。结构向导生成可编辑的源码；插入后按 Tab、Shift+Tab 依次选择参数。完整支持范围见 [命令兼容表](RELIEFMATH_COMMANDS.md)。这是一套离线数学子集；未知命令定位报错，不加载 TeX 宏包、文件、shell 或网络资源。

| 快捷键 | 操作 |
| --- | --- |
| Ctrl+N / Ctrl+O | 新建 / 打开 |
| Ctrl+S / Ctrl+Shift+S | 保存 / 另存为 |
| Ctrl+Z / Ctrl+Y / Ctrl+Shift+Z | 文档全局撤销 / 重做 |
| Ctrl+F / Ctrl+H | 查找 / 替换 |
| Ctrl+Space | 命令补全 |
| Tab / Shift+Tab | 下一个 / 上一个结构参数；无参数时标准焦点导航 |

源码变更经短暂合并后提交独立渲染进程。失败时保留最近成功图像，并标明“旧预览”和错误；“定位错误”选中对应源码。复制图片要求当前公式渲染成功，防止复制旧预览。PNG 文件保留透明度；图片剪贴板按 FLTK 支持转换为白底 RGB。

## 保存与导出

原生 `.rmath` 文档保留多条公式的名称、顺序、源码和样式。保存与读取在后台执行；保存的是开始操作时的快照，期间的新编辑仍标为未保存。外部修改会要求重新加载、另存为、明确覆盖或取消。正常切换和关闭前提示处理未保存修改。

导出支持 SVG、透明 PNG 和 LaTeX 源码，可选当前、选中或全部公式，并指定倍率、DPI、目录与 `{index}` / `{name}` 命名模式。扩展名自动添加。每项记录独立成功或失败，取消保留已经完成的文件。每一项都绑定开始时的源码与设置；不会把旧预览导出成新公式。

SVG 中的字形（含中文）转为实际曲线路径；接收方无需安装字体。预览、SVG、PNG 使用同一数学布局。后端与字体许可见 [渲染实现与证据](RELIEFMATH_BACKEND.md)。

首版限制：每文档 256 条公式、每条 64 KiB 源码、文档 16 MiB、嵌套 128 层；单边最多 16384 像素，总像素最多 16777216。超限明确失败，不静默截断。

恢复副本每 60 秒保存一次已修改文档；异常结束后，下次启动可恢复为新文档。原路径仅作提示，恢复不会直接覆盖原文件。收藏也使用 `.rmath`，独立于当前文档保存。

## 文档持久化实现

## `.rmath` v1 格式

`.rmath` 是显式编码的 little-endian 字节流；实现不会把 C++ 结构体直接写到磁盘。文件总长度必须与头部的 `total_bytes` 完全相等，不能包含尾随数据。文件上限为 16 MiB，解码只有在所有字段、UTF-8、记录数量、稳定 ID、样式限制和保留位均通过验证后才替换当前 `Document`。

| 顺序 | 字段 | 宽度 | v1 要求 |
| --- | --- | ---: | --- |
| 头部 | magic | 8 字节 | `RMATH\r\n\0` |
| 头部 | version | u32 | `1` |
| 头部 | total_bytes | u32 | 精确等于整个文件长度 |
| 头部 | formula_count | u32 | 等于后续记录数，最多 256 |
| 头部 | title_bytes | u32 | UTF-8 标题长度，最多 256 字节 |
| 头部 | next_id | u64 | 下一个稳定公式 ID |
| 头部 | title | `title_bytes` | UTF-8 字节，不含 NUL |
| 每条记录 | id | u64 | 非零且在文件内唯一 |
| 每条记录 | name_bytes | u32 | 名称长度，最多 256 字节 |
| 每条记录 | source_bytes | u32 | 源码长度，最多 64 KiB |
| 每条记录 | rgba | u32 | `RRGGBBAA` |
| 每条记录 | point_size | u16 | 按模型样式范围验证 |
| 每条记录 | padding | u16 | 按模型样式范围验证 |
| 每条记录 | display | u8 | 仅 `0` 或 `1` |
| 每条记录 | reserved | 7 字节 | 必须全部为零 |
| 每条记录 | name、source | 变长 | 分别紧随本记录头部，均为 UTF-8 且不含 NUL |

头部固定为 32 字节，每条记录头固定为 32 字节。`revision`、运行期 `generation`、渲染缓存和路径不持久化。版本不受支持、长度不一致、截断、重复 ID、非法 UTF-8、非零保留位或越界字段都会显式失败；失败时目标 `Document` 和文件戳保持原值。

## 读取、冲突与原子保存

`read_document(path, document, stamp, error, control)` 在临时字节缓冲区和临时 `Document` 中完成读取、摘要与验证，成功后才提交输出。文件戳包含设备号、inode、大小、修改/状态变更时间及内容摘要。符号链接、非普通文件和越界文件会被拒绝。

`atomic_save(path, document, expected, new_stamp, error, control)` 先检查目标是否仍与 `expected` 一致，再在目标同目录以独占创建方式写临时文件。写入会处理 EINTR 和短写；文件数据同步后重新核对冲突，最后在 rename 前再次采样取消状态。成功 rename 后同步父目录。rename 前失败会删除临时文件并保留原目标；父目录同步失败则返回 `Code::Io`，错误明确说明目标已替换但目录持久化未确认，且 `new_stamp` 会报告已安装文件。

`IoControl` 可选地在调用线程中提供 `cancelled(context)` 和 `progress(context, phase, completed, total)`。读写按最多 64 KiB 分块并在分块间检查取消；原子保存另在 rename 前检查。rename 完成后不会响应取消，而会继续同步父目录并按实际结果报告。两个回调都可为 null，默认调用不需要控制对象。调用者应在后台工作线程使用这些同步 API；回调也在该线程执行，不会调用 FLTK。

冲突检查只能检测戳支持的变化。没有配合锁的外部写入者仍可能在最终检查与 rename 之间修改目标，因此此接口不声称跨程序 compare-and-swap；覆盖冲突应由上层显式处理。

独立 raw 字节保存 API `atomic_save_bytes()` 上限为 128 MiB，以容纳协议导出的单工件（当前 PNG 和 RGBA 上限各为 64 MiB，SVG 为 16 MiB）。此上限不改变 `.rmath` 的 16 MiB 编解码限制。

## 恢复快照

恢复目录使用绝对 `XDG_STATE_HOME/reliefmath/recovery`；未设置有效绝对 `XDG_STATE_HOME` 时使用 `$HOME/.local/state/reliefmath/recovery`。没有有效绝对 HOME 时返回明确错误。目录路径逐级拒绝符号链接，最终目录归当前用户所有并设为 `0700`；快照与实例锁为当前用户的 `0600` 普通文件。

目录初始化在每次创建子目录后先 `fsync` 其父目录，再打开下一级；已存在的目录项也同步，覆盖失败重试或并发创建后留下的未确认状态。最终目录设为 `0700` 后再次同步其元数据。同步遇到 `EINTR` 会重试，其他失败返回 `Code::Io`，不提交输出路径或已打开的 `RecoveryStore`；失败可能留下目录，后续重试仍须完成同步。

每个实例以独立 ID 和 `flock` 锁占有自己的快照。另一个仍持锁的实例不可被列为可恢复项或接管；进程崩溃后锁释放，遗留快照可被发现。快照封装版本、精确长度、仅作显示的原文件路径提示和一个完整 `.rmath` v1 文档，并受 128 MiB raw 文件上限约束；内嵌文档仍受 16 MiB 限制。

恢复只把快照加载为新 `Document`，路径提示不会触发原文件覆盖。取消恢复保留快照；只有显式 `discard(id, error)` 才丢弃指定项。实例正常关闭时可调用 `discard_own(error)` 清理自身快照；没有自身快照时该调用成功且不影响其他实例。删除后目录同步失败会报告快照已移除、持久化未确认。

`RecoveryStore` 由单一工作线程独占访问时可安全调用同步的 `open`、`save`、`list`、`load`、`discard` 和 `discard_own`。UI 应在对应 job 完成后读取 `items()`；此容器本身不提供并发同步。恢复保存与加载接受同一可选 `IoControl`，供后台 job 取消及报告进度。
