# Installer firmware selection before partitioning

用户已要求直接实施，不增加计划审批步骤。

## 目标与约束

- 图形安装顺序：磁盘 → 引导方式 → 分区 → 账户 → 确认。更新安装：磁盘探测 → 引导方式 → 确认。
- BIOS、UEFI 可独立选择；默认双选，更新默认继承已安装的引导器。取消两者保留外部引导用法及明确提示。
- 自动 GPT 方案按选择生成：包含 BIOS 时为 1 MiB 未格式化 BIOS Boot、128 MiB FAT32 ESP、剩余 ext4；不含 BIOS 时省去 BIOS Boot。FAT32 分区是两种固件共用的启动资源存储，不能在 BIOS 模式删除。
- 预览不写盘。已确认执行的手动/自动分区不会因返回修改引导方式而再次写盘；缺少所选引导方式所需分区时阻止继续。
- TTY、安装执行、更新探测、校验、中文资源、文档和现有 QEMU 驱动保持一致。只使用自有临时虚拟磁盘做破坏性验证。

## 实施清单

1. 扩展 `model.h/.c` 导航和宿主模型测试，覆盖新装/更新的前进、后退、侧栏顺序。
2. 扩展 `installer_partitions.h/.c` 固件参数与几何校验；用真实 GPT 写入和独立 sfdisk 检查四种组合、拒绝无效方案及保留错误路径数据。
3. 更新 `install_ops.c` 全部方案调用和手动 BIOS 校验；更新成功探测进入引导方式页。
4. `main.cpp` 新增引导方式页，确认页只读汇总；分区页展示与选择一致的自动方案。TTY 在分区之前选择固件。
5. 更新翻译、安装说明及全部受影响 QEMU 自动化步骤；审计旧页码、固定三分区和旧确认页控件的残留。
6. 执行相关宿主测试、生产编译和 installer ISO staging 检查；QEMU 实际完成选择、分区、安装、移除介质后启动，并核对磁盘布局及 loader 文件。记录实际覆盖范围，不以 QEMU 代替 VMware 验证。

实现阶段不自动提交、推送或发布版本；后续提交与推送按用户明确授权执行。不修改内核。
