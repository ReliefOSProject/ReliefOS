## 组件契约

私有头 `kernel/reliefnt/kernel/reliefnt/include/reliefnt/vdso_data.h`：

```c
#define RELIEFNT_VDSO_CLOCKS 12
#define RELIEFNT_VDSO_MODE_NONE 0u
#define RELIEFNT_VDSO_MODE_TSC 1u
#define RELIEFNT_VDSO_SHIFT 32u
struct reliefnt_vdso_timestamp { int64_t sec; uint64_t nsec; };
struct reliefnt_vdso_data {
    uint32_t seq, clock_mode, clock_mask, hres_mask;
    uint64_t cycle_last, mult, max_cycles, resolution_ns;
    struct reliefnt_vdso_timestamp basetime[RELIEFNT_VDSO_CLOCKS];
};
void time_vdso_bind(struct reliefnt_vdso_data *data);
```

`seq` 配合 acquire/release 和读屏障保护快照；仅时钟 0、1、5、6 作为首版
加速对象。clock_mask 表示快照可用，hres_mask 指定需要计数器插值的时钟。
`mult` 是每 cycle 纳秒的 Q32 值，`max_cycles` 限定有效插值窗口。
数据符号 `__vvar_data` 在 ELF 基址前一页（-4096），隐藏，不输出到动态符号表。
构建 `$(O_GENERATED)/vdso/vdso.so`，嵌入符号
`reliefnt_vdso_image_start` / `reliefnt_vdso_image_end`。
映射层 `int vdso_map_task(struct task *task, uint64_t *ehdr)` 在 ELF 已装载、
栈向量尚未构建时调用；成功才向 auxv 放入 ehdr，不新增任务结构字段。

## 任务 2：时间数据发布与高精度连续性

负责文件：内核私有 vdso_data.h、time.c、time_discipline.c/.h（必要时）、
syscall_process.c 中 clock_getres 分辨率；父仓新测试
`tools/test_vdso_time.py`、`tools/tests/vdso_timekeeper_test.c`。

- [x] 先写并运行测试：实际 time.c 的共享快照、墙钟修改、COARSE、
      不可信/SMP 回退；负向纪律变化和 tick 边界无倒退。
- [x] time_vdso_bind 在 clock_lock 下初始化并发布；tick/settime/成功 adjust
      发布一致快照。不依赖用户页锁，不泄露内核指针。
- [x] 高精度仅单在线 CPU + 用户可读 invariant TSC + 有效校准时启用。
      必要时在此条件下建立连续 anchor/mult，tick 与调时按同一换算规则
      先结算已过时间再变更频率；不把不连续的旧 PIT 插值直接搬到用户态。
- [x] syscall 和 vDSO 的分辨率与换算一致；不可信高精度走原 syscall。
- [x] 实际代码宿主 ASan/UBSan 测试通过，记录既有失败与新测试分别结果。
