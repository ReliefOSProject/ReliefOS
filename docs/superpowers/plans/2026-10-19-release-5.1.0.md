# ReliefOS / ReliefNT 5.1.0 发布实施计划

> **For agentic workers:** 使用当前会话逐项执行；发布前以独立审查核对两仓范围与说明。

**Goal:** 两仓同步为 5.1.0，提交推送并通过 gh 各发布一份内容独立的源码 Release。

**Architecture:** 沿用数字版本机制，分别维护版本输入与发布说明；内核先推送，主仓再更新 gitlink。

**Tech Stack:** GNU Make、Git、GitHub CLI、现有 C 版本生成器与宿主测试。

**Spec:** 用户 2026-10-19 的发布请求及选项回答；长期规范见 `docs/RELEASE_PROCESS.md`。

## Global Constraints

- 最新指令将目标从 5.0.0-rc1 改为 5.1.0，按正式版本发布。
- 范围为两仓各自 5.0.0 版本提交之后到本次版本提交；仅源码，不上传二进制。
- ReliefOS 起点 `6894edc64ba663193ec9139732e704f93b0d0b24`；ReliefNT 起点 `f8f5a4908807e81cca7ed766fb6c60e7829767dc`。
- 两份 Release 格式相同、内容独立，不列纯版本号或 gitlink 更新；规则写入两仓文档和 AGENT.md。
- 用户已授权提交、推送、发布；不另建分支、不合并主仓 main、不强推。
- TMPDIR 使用父仓 out/tmp；不提交输出或无关文件，不改 ABI golden 和音频 manifest。

## Review Focus

- 系统身份不能仍显示 4.x；核对版本输入、生成宏和 os-release。
- 主仓 Release 不能复制内核实现；混合提交只提主仓部分。
- ReliefMail 开发源码不能被称为默认镜像完整集成。
- 现有 ABI 布局差异不能用改 golden 掩盖；如失败保留并披露。
- 标签必须指向对应新版本提交，不能误用主仓默认分支。
