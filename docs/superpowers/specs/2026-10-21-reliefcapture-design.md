# ReliefCapture 设计

用户已选定截图工具，并要求 IceWM 的 Win+Shift+S 调出类似 Windows 的截图体验。
沿用用户此前授权：直接实施，无需再次审批计划；本任务不提交、不推送、不建分支。

## 使用流程

- 普通启动打开原生 C++17 / FLTK gtk+ 编辑窗口；不属于 ReliefOffice。
- `reliefcapture --select` 直接冻结桌面，显示区域、窗口、全屏选择条。
  IceWM 系统默认键位将 `Super+Shift+s` 绑定到这一入口。
- 先在后台取得没有自身窗口的 Xorg 根窗口快照，再显示覆盖层。区域模式拖动选框，
  窗口模式高亮并选择当时可见的普通窗口（包括边框），全屏模式截取整个 X 屏幕。
  Esc 或右键取消，取消时恢复原编辑内容；不产生文件。
- 截图进入编辑窗口并复制图像到 X11 剪贴板。提供手动复制、保存 PNG、重新截图、
  0/3/5/10 秒延时；剪贴板由本进程持有，退出后不保证保留。
- 标注支持画笔、箭头、矩形、UTF-8 文字、颜色、线宽、撤销和重做；支持适应窗口
  与 100% 显示。截图内容和导出尺寸保持原始像素。

## 技术边界

- X11 屏幕读取及 PNG 编码、保存由独立工作进程完成。GUI 轮询有界非阻塞通道，
  允许取消和正常关闭，只回收自身子进程。无外部截图命令、无提权。
- 单张最多 16,777,216 像素、每边最多 8192；超过上限明确报错，不静默裁切。
  最多 512 条标注，每条画笔最多 8192 点，文字最多 1024 UTF-8 字节。
- 原生控件保留 FLTK 默认主题；覆盖层的变暗、选框和尺寸提示是截图功能反馈。
- 编辑器内容区直接显示紧凑的截图与标注工具栏，不放程序大标题或介绍横幅；程序名在窗口标题栏。
- PNG 原子写入，保留已有文件直到成功；拒绝符号链接和非普通目标，替换已有文件
  要确认，发布前再次校验目标身份，发现冲突时保留原文件。
  已有文件采用普通 POSIX 检查后原子替换语义，不声称跨进程条件式原子提交。
- 同一用户、同一 DISPLAY 的实例通过 X11 selection 协调：重复快捷键唤醒已有实例，
  不叠加多个选区；正在保存时保留工作并给出状态。
  次实例发送 ClientMessage 后完成 XSync 往返再退出。隐藏编辑器前预留 Esc，
  同时识别已排队到旧窗口的 Esc，覆盖隐藏到读取屏幕之间的取消操作。
- 初版不含录屏、滚动长截图、OCR、自动上传和自由形状选区。窗口截图得到的是冻结
  桌面上实际可见的矩形区域，遮挡部分不会被重建。

## 验收

先测试坐标裁剪、缩放映射、标注撤销与边界、PNG 原子保存和冲突，再编译应用与翻译。
检查组件、桌面文件、图标、APK 归属、IceWM 配置进入镜像。
QEMU 普通用户实际按 Win+Shift+S、拖动选区、Esc 取消、窗口/全屏、延时、标注、
复制、保存和关闭；回读 PNG 核对尺寸、内容与标注，并给出真实截图。
编译、镜像读回、私有 QEMU 及 VMware 分别报告；VMware 验证未完成时明确注明。
