# ReliefAPK 图形包管理器设计

日期：2026-10-18

状态：用户已批准，2026-10-18 开始实现。

## 目标与现状

为 ReliefOS Xorg 内置一个 C++17、FLTK 图形包管理器，程序暂名
ReliefAPK，命令为 `reliefapk`。沿用现有 FLTK 主题、中文字体与国际化约定，
操作以软件包、变更预览和进度为中心，不在窗口内容区重复程序大标题。

用户已选择沿用现有界面风格，完成后查看真实系统截图，不制作独立网页原型。

仓库固定使用 apk-tools 3.0.8-r0。已在现有构建根目录上实际运行
`apk query --installed --format json --fields name,version,description,installed-size,status '*'`，
成功取得 201 条记录。所有软件包查询、依赖解析、版本选择、下载和事务均调用
`/sbin/apk`，不自行读取或修改 apk 二进制数据库，不重新实现依赖求解器。
当前构建的 apk 不包含内置帮助文本，程序提供自身的操作说明。

现有系统提供上游 sudo、su 和 PAM，以及图形 askpass。沿用系统认证规则。
初始镜像的远程索引可能尚未缓存：这应显示为“需要刷新索引”，不能把缺少索引
或网络故障显示成“没有软件包”。

## 界面方案

采用列表工作台：左侧为“全部软件包、已安装、可升级、world 包及依赖、孤立包”
筛选，中央为可排序的软件包表格，右侧或下方为所选包详情。
顶部保留搜索、刷新索引、升级系统、本地安装和应用变更；底部为简短状态。
待执行变更和运行日志使用独立面板或窗口，避免每页重复相同内容。

比较的其他布局：单包操作窗口适合偶尔安装，但批量操作不方便；
逐步向导适合第一次使用，但频繁搜索和维护步骤过多。因此选择列表工作台。

最小窗口适应 1024×768 桌面；允许缩放、调整列表与详情的比例。
使用原生 FLTK 表格、菜单、分隔面板、文件选择器和密码输入组件。
按钮名称直接表示操作，危险选项默认关闭，较少使用的选项放在工具或高级选项中。
中文与英文标签均可读，支持键盘搜索、选择和常见快捷键。

## 功能范围

### 软件包与查询

- 名称及描述搜索；已安装、可升级、world 包及依赖和孤立包筛选。
- 名称、已安装版本、候选版本、状态、大小、描述等表格列。
- 详情显示架构、来源、许可证、主页、依赖、反向依赖、提供项、文件列表和仓库策略。
- 根据文件路径查询所属软件包。
- 查看标准 `/etc/apk/world` 文本约束；版本约束和仓库标签通过 apk 命令管理。
  侧栏遵循 `apk query --world` 的原生含义，展示 world 及其依赖，不标为“手动安装”。

### 安装与维护

- 安装、卸载、选定包升级、全系统升级、重装和修复。
- 安装本地 `.apk`，下载软件包到用户选择的目录，可选包含依赖。
- 支持多选批量操作和撤销尚未执行的选择。
- 安装、删除、升级和修复前运行 `--simulate`，展示原始模拟输出及变更摘要；
  失败时保留错误原因，不进入实际执行。
- 同一种操作合并执行；不同操作类型按明确顺序执行，不把多次 apk 事务宣称为一次原子事务。
- 涉及后续操作时重新模拟；失败后停止余下操作，并重新查询实际状态。
- 显示实时阶段、进度、命令、退出状态与可复制或保存的日志。
- 查询和下载允许取消；事务提交阶段避免强行终止，关闭窗口时明确提示仍在执行。

### 工具与配置

- 仓库地址、标签、启用状态、顺序的可视化编辑；保留注释及不认识的配置行。
- 展示生效的 repositories 文件和受支持的 repositories.d 文件；修改只作用于明确选中的文件。
- 保存前校验，使用相同目录中的临时文件、同步和原子替换，保留一份备份；
  检测外部修改冲突并保留原文件权限。
- 缓存查看、清理、下载缺失缓存；配置受 apk 支持的缓存与索引刷新选项。
- 离线模式、索引刷新频率、网络超时；不自动启用不可信签名或关闭 HTTPS 验证。
- 查看可信密钥及其文件来源；不自动添加未知密钥。
- 包完整性和签名校验、系统文件变更审计、软件包统计、版本比较。
- 查看和导出依赖 DOT、包清单等文本诊断结果。

上述覆盖日常使用的大多数 apk 命令。首版不提供制作和签名发行包、
生成仓库索引以及底层数据库转换的专用向导；这些属于发行维护工作。

## 响应性与进程执行

- FLTK 主线程只处理输入、绘制和有时间预算的结果更新。
- 所有 apk 命令使用独立进程与非阻塞管道，按参数数组执行，
  不使用 shell 命令拼接，不使用阻塞 `system()` 或 `popen()`。
- apk 在独立进程中运行，输出按字节及对象预算分段解析；表格按可见行绘制，
  不为每个包创建 widget。完成时进行有输入上限的排序，并测量最大单段耗时。
- 搜索约 300 毫秒防抖；结果核对当前请求、选中包及版本，过时结果不覆盖新选择。
- 元数据按需查询，复用当前结果；安装或刷新后只使相关缓存失效。
- stdout、stderr、进度分别处理；日志在界面中的长度有上限，避免大量输出拖慢绘制。
- 软件包名称和描述作为纯文本呈现，不能成为 FLTK 格式串、shell 片段或命令选项。
- 同时最多一个修改事务；apk 原有数据库锁仍然生效，锁冲突显示可理解的错误。

## 权限与认证

普通用户能够先浏览和搜索，实际修改时再提权。已是 root 时直接执行。

认证方式提供两项：

1. sudo：提示输入当前用户的 sudo 密码，遵循 sudoers/PAM 和原有凭据有效期。
2. root 密码：通过系统 su/PAM 验证 root，作为没有 sudo 授权时的显式选择；
   root 被锁定或 PAM 拒绝时显示实际原因。

GUI 保持原来的用户身份，只将选定操作交给固定路径的工作进程。
提权只授权所选工作，不通过修改 sudoers 或设置免密获取权限。
密码通过专用匿名管道或标准终端认证通道传递，不进入参数、环境变量、
日志或磁盘；使用后清理内存，认证失败与用户取消分开处理。
root 工作进程重新验证操作类型、参数和配置目标。

图形认证沿用系统机制或提供同风格的 FLTK 认证窗口；
不以 root 身份重启整个桌面 GUI。

## 代码边界与集成

源码放在 `userland/apps/reliefapk/`：

- 软件包模型、结构化输出解析与约束校验。
- 异步子进程执行及认证。
- 操作队列、模拟和执行状态。
- 仓库配置读取、修改校验与特权保存。
- FLTK 主窗口、详情、工具、设置和进度窗口。

接入组件清单、FLTK 构建、默认镜像、APK 文件归属、菜单、
标准 desktop 文件和自写图形程序图标；复用既有打包与图标系统。
不修改内核接口。

## 验证与交付

- 主机侧测试：真实 apk JSON、异常及截断输出、UTF-8、参数边界、
  注入字符串、模拟失败、队列失败处理、仓库注释及标签保留和外部修改冲突。
- 与真正 apk 的集成测试在隔离根目录和签名测试仓库进行，
  验证搜索、依赖、安装、升级、重装、卸载、本地安装和校验。
- 验证大量软件包、慢命令、输出洪泛时主窗口仍能响应；
  检查过时搜索、取消、日志长度和退出后的子进程清理。
- 构建目标系统 musl ELF，运行组件、打包归属和相关桌面集成检查。
- 使用私有 QEMU 镜像在 ReliefOS Xorg 中验证中文、
  普通用户启动、sudo 密码错误及正确路径、root 密码认证、实际包事务和配置保存。
- 截取软件包主界面、变更预览或执行进度、仓库设置等真实截图。
- 最终将编译、测试、系统内运行结果分开报告，明确实际测量的响应性与未验证部分。
  VMware 验证未完成；不能将 QEMU 结果代替 VMware 或真实硬件验证。
