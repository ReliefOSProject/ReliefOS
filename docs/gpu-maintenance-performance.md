# GPU 空闲清理与管道吞吐

本次在前一轮 Candidate D 上继续优化，每个普通系统调用仍先进入同一个执行事务。没有改动管道容量、PIPE_BUF 原子写、用户缓冲区检查、系统调用返回资格或调度策略。

## 定位与实现

临时诊断把 read/write 的执行事务拆成 GPU 清理、音频与输入、描述符 pin、实际分派、结果与存储清理、描述符释放以及返回调度。只记录同核原始 TSC cycles，避免跨核相减；计数在负载前后冻结，结束后才输出。第一轮因诊断表容量不足失败，未取得性能数据；缩小到 read/write 后重新测量，所有快照的 dropped/bad_clock 均为 0。诊断代码已从产品移除，正式测速使用无插桩内核。

插桩的双核管道样本中，GPU 清理约占执行锁持有周期的 17%–19%。旧实现即使没有待回收对象，也进入资源队列锁、执行队列锁和 SVGA 后端锁，扫描 shader 记录。新实现为这些空路径提供保守的工作提示：

- DRM 资源队列在原锁下发布是否非空，入队、弹出及失败重新入队都更新提示；实际对象访问仍在原锁下进行。
- Exec 清理提示覆盖已分配工作、已提交工作、失败清理、continuation 清理和缓存 attachment。把尚未入队的已分配工作也计为有工作，以免过早跳过。
- SVGA shader 的提交销毁路径统一发布退休位图，真实 fence 通过并清除记录时移除对应位。没有退休 shader 时，清理器直接返回；有工作时仍按原轮转顺序和预算扫描、检查 fence，并在锁外释放 backing。

提示只用于观察空状态，读取它不会消费对象或替代队列锁。在空观察之后发布的工作留在原队列，由下一次系统调用或已有的 idle timer 服务处理；没有新增定时节流或跳过真实 fence。KMS 的待呈现、损伤和 framebuffer 恢复服务始终执行。Linux 用户结构、系统调用号与参数 ABI 均未改变，也没有重生成 ABI golden。

## 验证方法

证据位于 `out/io-throughput-20261020/`。起点 D 的内核 SHA-256 为 `43bf69b918d525ac041a23fc3fb4d0b43be2f0d101383439d8f0c0b47cf71c9a`，候选 E 为 `cc5c07f4d17099071db2dd6ab72c5adc6eb5de00a5365733f629acbdb34d2cbb`。候选两端使用相同用户态与根文件系统，只替换内核；私有镜像两份 ESP 内核均回读核对，根分区与源镜像摘要核对不变。

QEMU/KVM 使用 4 GiB 内存，分别测 1/2/4 vCPU。每轮各三次：

```sh
# 默认 bs=512，每次 256 MiB
yes | dd of=/dev/null count=524288 iflag=fullblock status=progress
# bs=64 KiB，每次 1 GiB
yes | dd of=/dev/null bs=65536 count=16384 iflag=fullblock status=progress
```

两种块大小分别统计，不把参数变化算成内核收益。使用同一探针的 CLOCK_MONOTONIC 耗时与完整传输字节数计算十进制 MB/s；测速退出状态、SMP 时间检查和正常 VM 关闭均单独检查。宿主机有其他任务，未隔离 CPU，数据只代表本机本轮观测。

Host 回归先在旧实现上复现空闲维护仍取得 GPU 锁，以及有活跃 shader 但无退休工作时仍与无关 GPU batch 争锁。修改后检查空闲路径和新 continuation 入队后的重新激活；现有完整 DRM/SVGA fixture 覆盖 fence 未到达时保留 backing、事务提交/回滚、上下文销毁、回收预算和无 DMA 页泄漏。ASan/UBSan 用于实际产品代码 fixture。新增 shader 用例调整到原有序列之后，以免改变原用例依赖的静态轮转游标；不修改产品轮转策略或原断言。

内核按 canonical `O=out/debug PROFILE=debug` 构建。管道唤醒、pselect、系统调用返回与真实调度/执行锁回归另行检查。前一轮完整 memory suite 的两个旧 fixture 编译失败、音频产物与 ABI golden 决策项不属于本次修复，仍保留原记录。
