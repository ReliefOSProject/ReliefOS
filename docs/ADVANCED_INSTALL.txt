ReliefOS Installer ISO - Advanced Installation Quick Guide
==========================================================

Read: less /root/ADVANCED_INSTALL.txt

The same Installer ISO supports Legacy BIOS and UEFI. Select
"Install ReliefOS (console session)" to start a root Bash shell; run installer for the supported interactive installer.
GUI and TTY fresh installs default to Xorg and both bootloaders. Each loader
can be skipped independently. Skipping both on a new disk requires an external
bootloader. Updates retain the detected desktop profile and existing loaders.

Manual copying does not provision accounts or the installed-system marker.
Use the regular installer for a supported root/user login and sudo policy.
These steps are for repair and development. They require a 512-byte logical
sector disk and enough space for /install/root plus future data.

WARNING: The partitioning/formatting commands below destroy target data.
Verify the disk using lsblk and fdisk -l. /dev/sda is only an example; NVMe
uses /dev/nvme0n1 and /dev/nvme0n1p1 etc. Never select the installation medium.

1. Check the source and target
------------------------------

ls /install/root /install/root-console /install/esp
lsblk
blkid
fdisk -l

2. Create the default three-partition GPT
-----------------------------------------

The upstream sfdisk command below replaces the target partition table.
Do not run it on an existing system you intend to update.

sfdisk /dev/sda <<'TABLE'
label: gpt
unit: sectors

start=2048,size=2048,type=21686148-6449-6E6F-744E-656564454649,name=RELIEFOS_BIOS
start=4096,size=262144,type=U,name=RELIEFOS_ESP
type=L,name=RELIEFOS_ROOT
TABLE
sync
sfdisk --verify /dev/sda
lsblk /dev/sda

Partition 1: unformatted 1 MiB BIOS Boot space. NEVER format or mount it.
Partition 2: 128 MiB FAT32 ESP shared by BIOS GRUB files and UEFI application.
Partition 3: ext4 root using remaining space.
Manual layouts may use different indices; supply actual device paths below.

3. Format and check only ESP and root
-------------------------------------

mkfs.fat -F 32 -n RELIEFOS /dev/sda2
mkfs.ext4 -F -L RELIEFOS_ROOT /dev/sda3
fsck.fat -n /dev/sda2
fsck.ext4 -f -n /dev/sda3
blkid /dev/sda2 /dev/sda3

Do not format a whole disk or mounted partition. mkfs.fat32 is an alias for
mkfs.fat and still needs the explicit -F 32 option.

4. Mount and copy
-----------------

mkdir -p /mnt/root /mnt/esp
mount -t ext4 /dev/sda3 /mnt/root
mount -t vfat /dev/sda2 /mnt/esp
cp -a /install/root/. /mnt/root/

For a text-login installation copy /install/root-console instead.
-a preserves links, permissions and timestamps. Do not copy into /target,
which belongs to the regular installer.

5. Bind the root and ESP identities
-----------------------------------

ROOT_PARTUUID="$(blkid -s PARTUUID -o value /dev/sda3)"
ESP_PARTUUID="$(blkid -s PARTUUID -o value /dev/sda2)"
printf 'root=%s\nesp=%s\n' "$ROOT_PARTUUID" "$ESP_PARTUUID"

Both values must be nonempty unique UUIDs; otherwise stop and inspect GPT.

cat > /mnt/root/etc/fstab <<EOF_FSTAB
# source mountpoint type options dump pass
/dev/disk/by-partuuid/$ROOT_PARTUUID / ext4 defaults 0 1
/dev/disk/by-partuuid/$ESP_PARTUUID /boot vfat defaults 0 2
EOF_FSTAB

6. Install both bootloaders through the shared API
--------------------------------------------------

reliefos-boot-install --source /install/esp --boot-directory /mnt/esp \
    --disk /dev/sda --root-partuuid "$ROOT_PARTUUID" --bios=yes --uefi=yes --check
reliefos-boot-install --source /install/esp --boot-directory /mnt/esp \
    --disk /dev/sda --root-partuuid "$ROOT_PARTUUID" --bios=yes --uefi=yes

--check validates without publication. --bios=no or --uefi=no skips that
loader. --update preserves prior rollback files and detected mode records.
BIOS installation invokes GNU grub-install with explicit argv; it requires
unmounted dedicated BIOS Boot space. UEFI uses EFI/BOOT/BOOTX64.EFI without
NVRAM registration. Both share the current kernel and menu. root.cfg records
the selected PARTUUID, so another disk with the same filenames is not selected.

The old leonos-grub-installer command is a UEFI-only update wrapper. It does
not create BIOS embedding space. Existing two-partition UEFI installations
can update with BIOS skipped, without changing partition tables or user files.
A request to add BIOS without BIOS Boot space is rejected before publication.

A complete boot transaction is not power-failure atomic. On an error, inspect
the reported stage before rebooting; do not assume a failed tool rolled back
all disk writes. The common menu is published only after successful stages.

7. Finish
----------

sync
cd /
umount /mnt/esp
umount /mnt/root
reboot

Remove the ISO or choose the installed disk in the firmware boot menu.
If unmount reports busy, close programs and leave the mount directory first.

Troubleshooting
---------------
No BIOS Boot space: use the regular fresh installer or intentionally create
  dedicated unformatted BIOS Boot space; do not overwrite an existing partition.
Preflight rejects the disk: confirm the whole disk, writable state, source/target
  separation, mounted ESP ownership, partition types and selected root UUID.
UEFI-only manual disk: select --bios=no. Do not repartition an update target.
No login after manual copying: manual copying omits account provisioning;
  use the supported regular installer.
Firmware cannot see NVMe: kernel NVMe support does not add an NVMe driver to
  legacy firmware. Use firmware that can load GRUB from that device.
