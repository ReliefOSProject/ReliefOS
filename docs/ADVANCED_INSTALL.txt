ReliefOS Installer ISO - Advanced Installation Quick Guide
==========================================================

Read this guide with: less /root/ADVANCED_INSTALL.txt

Select "Install ReliefOS (TTY mode)" from the Installer ISO boot menu. The
entry starts a root Ash shell. Run "installer" to launch the interactive TTY
installer, or continue with this guide for a manual installation.

The TTY environment provides standard Linux command-line tools: fdisk, mount,
lsblk, and blkid from util-linux; mkfs.ext4 and fsck.ext4 from e2fsprogs;
mkfs.fat and fsck.fat from dosfstools; mkfs.exfat and fsck.exfat from
exfatprogs; and the standard BusyBox file utilities.

WARNING
-------

The partitioning and formatting commands below destroy data on the target
disk. The examples use /dev/sda. NVMe disks use /dev/nvmeXnY and partitions
use /dev/nvmeXnYpZ. Verify the actual target by its size and controller, and
do not overwrite the Installer ISO or another data disk.

Copying the payload manually does not run the regular installer's account
transaction and does not create the installed-system marker. Use the regular
installer when you need a supported root account, ordinary user account,
wheel/sudo policy, and a system that is immediately ready for login. This
guide is primarily intended for low-level installation, repair, and
development.

1. Check the installation source and target disk
------------------------------------------------

ls /install/root
ls /install/esp
lsblk
blkid
fdisk -l

2. Create a GPT and two partitions
----------------------------------

Run:

fdisk /dev/sda

Enter the following commands in order. A blank line means accept the default:

g
n
1

+128M
n
2


t
1
1
p

The result should contain partition 1 as an approximately 128 MiB EFI System
partition and partition 2 as a Linux filesystem partition using the remaining
space. Enter w to write the table when it is correct, or q to quit without
saving.

Partition names are optional. To assign names before entering w, use the
expert menu:

x
n
1
LeonOS 4 ESP
n
2
LEONOS4_ROOT
r

Use p to inspect the result and then enter w. The g command in the current
fdisk creates a GPT directly; running gptinit first is no longer necessary.

Check the new partition table and device nodes:

sync
lsblk /dev/sda
fdisk -l /dev/sda

3. Format and check the filesystems
----------------------------------

mkfs.fat -F 32 -n LEONOS4ESP /dev/sda1
mkfs.ext4 -F -L LEONOS4ROOT /dev/sda2
fsck.fat -n /dev/sda1
fsck.ext4 -f -n /dev/sda2
blkid /dev/sda1 /dev/sda2

mkfs.fat32 is only a link to mkfs.fat. You must still pass -F 32 when using
that name. Do not format the whole /dev/sda device, and do not format a
mounted partition.

4. Mount the target filesystems
------------------------------

mkdir -p /mnt/root /mnt/esp
mount -t ext4 /dev/sda2 /mnt/root
mount -t vfat /dev/sda1 /mnt/esp
mount

5. Copy the system
------------------

cp -a /install/root/. /mnt/root/

The -a option preserves symbolic links, permissions, and timestamps. Check
the copied runtime:

ls -l /mnt/root/usr/lib/reliefos/apps/desktop/desktop.elf
ls -l /mnt/root/lib/ld-musl-x86_64.so.1

6. Write /etc/fstab
-------------------

ROOT_PARTUUID="$(blkid -s PARTUUID -o value /dev/sda2)"
ESP_PARTUUID="$(blkid -s PARTUUID -o value /dev/sda1)"
printf 'root=%s\nesp=%s\n' "$ROOT_PARTUUID" "$ESP_PARTUUID"

Both values must be non-empty UUIDs. Then enter:

cat > /mnt/root/etc/fstab <<EOF
# <source> <mountpoint> <type> <options> <dump> <pass>
/dev/disk/by-partuuid/$ROOT_PARTUUID / ext4 defaults 0 1
/dev/disk/by-partuuid/$ESP_PARTUUID /boot vfat defaults 0 2
EOF

Verify the result:

cat /mnt/root/etc/fstab

7. Install the prebuilt UEFI/GRUB payload
----------------------------------------

leonos-grub-installer /mnt/esp

This command copies EFI/BOOT/BOOTX64.EFI, reliefos/kernel.sys,
leonos/kernel.sys, and the grub directory from /install/esp. It is not
GNU grub-install. It does not format or mount the ESP and does not create a
firmware NVRAM boot entry.

8. Synchronize, unmount, and reboot
----------------------------------

sync
cd /
umount /mnt/esp
umount /mnt/root
reboot

If umount reports that a target is busy, make sure the shell is not inside the
mount point and close programs using files on that filesystem. Remove the
Installer ISO before rebooting, or select the target disk in the firmware boot
menu.

Optional exFAT root filesystem
------------------------------

ext4 is the default. To use exFAT, set partition 2 to the Microsoft basic data
GPT type and replace the ext4 format, check, and mount commands with:

mkfs.exfat -L LEONOS4ROOT /dev/sda2
fsck.exfat -n /dev/sda2
mount -t exfat /dev/sda2 /mnt/root

Also change the root filesystem type in /etc/fstab from ext4 to exfat.

Troubleshooting
---------------

fdisk reports no partition table:
  Open the disk in fdisk and enter g to create a GPT.

The ESP was not formatted as FAT32:
  mkfs.fat requires the explicit -F 32 option.

mkfs reports that the device is busy:
  Use an unmounted /dev/sdXN or /dev/nvmeXnYpZ partition device.

PARTUUID output is empty:
  Do not write fstab. Check the GPT and device nodes with fdisk -l and lsblk.

Copying the boot files fails:
  Check that /install/esp is complete and /mnt/esp is the mounted ESP.

The installed system has no usable login account:
  Manual payload copying does not provision supported accounts. Use the
  regular installer instead.
