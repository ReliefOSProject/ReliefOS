==================
支持范围与已知限制
==================

验证层次
========

必须分别报告源码检查、编译、镜像打包、实际运行。历史单项成功不代表
本次源码、全部应用或完整安装升级路径成功。VMware 验证未完成；物理硬件未验证。
本次文档重组不修改这些运行状态，也不等于新一轮硬件验收。

运行限制
========

* 默认 OVMF 的部分高地址 NVMe BAR 超出现有 direct map 支持范围。
* 强制关机后的 Xorg 锁文件可能阻止桌面恢复。
* 编译压力下 IceWM 拖动与延迟问题尚无完整修复验收证据。
* ReliefMath 曾在关窗时退出 139，尚未完成根因修复和最终复验。
* 图形接口受实际 SVGA-II/VGPU9 能力限制，不承诺所有 GPU、Mesa 功能、
  跨设备 DMA-BUF、atomic modesetting 或硬件 vblank。
* 可加载 ``.ko`` 必须针对匹配的 ReliefNT ABI 编译，不支持直接加载 Linux
  原版二进制模块或任意 Linux 内部 API。实际配置与管理见
  :doc:`kernel-modules`。

测试基线
========

历史 soundctl APK 归属缺失已在当前策略中补齐；APK 归属测试同时覆盖
Python 3.10 与严格宿主 umask 的场景。驱动 ABI 保留 168 字节原始前缀，
版本 2 的 17 个追加服务字段通过单独夹具校验，总长为 304 字节；
原始 golden 未重生成，旧版本驱动描述符在 init 前拒绝。
音频支持清单检查验证声明的前提、证据和范围，不再固定要求所有运行标志
为未验证。音频产品检查仍需要实际构建产物；部分旧 fixture 及完整系统的
既有问题仍须单独复验，不宣称公开总测试全部通过。
Linux/POSIX 定向测试通过不能视为全量兼容认证；完整本机自举也未完成。
报告失败时保留原始命令、配置、返回码和日志，不能放宽断言后宣称通过。
