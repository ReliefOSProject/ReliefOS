========
发布规范
========

版本与范围
==========

发布版本由本仓 configs/build-version 的版本提交确定，标签为 v<版本>。
更新范围严格为（上一版本提交，本次版本提交]。独立检查两仓历史，合并去重，
只汇总最终生效功能；不列版本号更新、纯 merge 或纯 gitlink 等机械条目。
ReliefOS 只写主仓内容，ReliefNT 只写内核内容。
起点不唯一时列出具体提交选项并由维护者决定。

说明与验证
==========

正文依次包含“更新内容”“破坏性更新”“更新与迁移注意事项”“开发者提示”。
破坏性更新明确写是、否或尚未确认，列明路径、ABI、数据或工作流影响。
规范原文归档为 Documentation/releases/<版本>.rst；GitHub Release 使用
经审阅、内容相同的 Markdown 正文文件，可暂存在输出目录，不新增第二套手册。
源码发布不附二进制；只有明确选择时才从本版本重建并附校验和及归属。

核对主仓 VERSION_ID、两仓版本生成与数字宏；不改变 ABI golden 或音频策略
掩盖失败。编译、打包、QEMU、VMware 逐层报告，未验证明确注明。

提交与发布顺序
==============

只有用户明确授权才提交、推送、建分支或发布。先提交验证并推送 ReliefNT，
再更新父仓 gitlink、提交推送 ReliefOS。标签指向各自完整版本提交 SHA，
不能误用默认分支或擅自合并开发分支。已有标签和 Release 不静默重写。

通过 gh release create 的 verify-tag、target 和 notes-file 参数发布；预发布
另标 prerelease。回读确认标签解析的提交、正文、状态及附件，不以命令已发出
替代发布成功。
